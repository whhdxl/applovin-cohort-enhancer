# AppLovin 报表增强插件需求文档

版本：v0.1.7。更新时间：2026-09-19 16:35（北京时间）。

本文记录当前对话已确定的需求。标有“建议默认值”或“待实测”的内容属于待验证的产品或技术细节，不代表已经实现。

## 1. 目标与使用场景

在 AppLovin Ads 原生报表中提供区间着色、同期群计算指标、收入增长系数及留存衰退系数，帮助投放人员观察付费转化、用户价值、回收增长与留存变化。日常只打开部分原始列时，插件根据实际可用字段提供增强列；用户仍可决定每个增强列是否展示。

核心体验：选择报表 → 选择增强指标和周期 → 在原生表格中查看结果；切换原生列、日期、分组和筛选后，增强结果同步更新。

## 2. 当前事实与验证边界

以下来自本次对话中对已登录页面的只读检查，并非接口契约：

- 当前地址位于 `ads.applovin.com/analytics/reports`；实际需要支持的域名以实施时核验为准，不默认申请全部网站权限。
- 页面含日期与筛选区、Columns 按钮、Cohort／Real time 切换、导出、横向滚动表格、Total 行和分页。
- 检查时为 UTC、Cohort 模式，按 Week 与 Campaign 分组。
- 表头和数据主体在可访问性树中表现为两个独立 table。真实 DOM、虚拟滚动机制、选择器和网络响应尚未检查。
- 原生字段包括 Installs、Spend、CPI、IAP／IAA／Total 收入及 ROAS、Unique purchasers、CPP 和留存。
- 明确带周期的收入与 Unique purchasers 字段共同覆盖 D0、D1、D3、D7、D14、D28。
- 页面另有 1Y 收入、D60／D90／D180 ROAS、无周期的 Unique purchasers 等，不能直接假定它们可与其他周期互换。
- 检查行的 IAA 收入全部显示为零；尚未确认是真实零收入还是回传不完整。
- 部分远期列已显示数值，但当前同期群未完整走完相应窗口，不能仅凭有值判为成熟。

## 3. 第一版范围

### 包含

1. Cohort 模式下的 Unique 付费率、IAP ARPPU、IAP／IAA／Total RPD。
2. 以 Installs 为分母的同期群 ARPU 别名，不生成一套重复数据列。
3. IAP／IAA／Total 的 RPD 和 ROAS 增长系数。
4. D3/D1、D7/D3、D14/D7、D28/D7、D7/D1、D28/D1 留存衰退系数。
5. 原生数值列与增强数值列的可配置区间着色。
6. 每个增强列的显示开关、计算能力提示、设置本地保存和插件总开关。
7. 原生筛选、列变更、排序、分页及滚动后的同步更新，以及 Total 行的正确处理。

### 不包含

- 独立后台、云端报表、账号体系、报表上传和跨设备同步。
- 预测 LTV、预测回本天数、任意公式编辑器。
- 投放预算、出价、Campaign 等外部业务状态修改。
- 新增列的跨全量数据排序、扩展官方导出或修改官方保存报表内容。
- 缺失字段时自动调用额外接口、索取 Report Key 或主动加载全报表。
- IAA／Total ARPPU 的默认实现：当前缺少付费用户群自身的 IAA 收入，见第 5 节。

## 4. 指标口径与基础字段

### 4.1 统一定义

- `N`：当前行同期群的 Installs，不称为自然下载量或全产品去重用户数。
- `S`：该同期群的 Spend。
- `P[n]`：该同期群截至 Dn 的去重付费人数。
- `I[n]`、`A[n]`、`T[n]`：同一同期群截至 Dn 的累计 IAP、IAA、Total 收入。
- `ROAS_X[n]`：收入类型 X 的累计 ROAS，计算层统一为比例值；例如 2.14% 转换为 0.0214。
- `CPI = S / N`，仅在相同统计范围下成立。

所有参与计算的字段必须匹配账号、报表查询、分组、收入类型、币种和统计口径。不同周期是对同一同期群的累计观察点，不能混入 Real time 数据。

Dn 的日界线、累计窗口端点及回传延迟需要核验 AppLovin 当前应用推广报表定义；不得直接套用电商、MAX 或其他归因平台的时间规则。

### 4.2 字段获取原则

第一版以实际可读取的页面字段为准。“可读取”不只指屏幕视口内可见，但不能假定隐藏列存在于 DOM。

- 不从 Campaign 名称推测稳定 ID、目标类型或目标周期。
- 原生收入金额优先于由显示 ROAS 反推的收入。
- 未来若证实页面已加载响应包含隐藏字段，可以扩展取数能力；本版不预先依赖这一点。
- 不得通过混合多个查询结果补齐一条行数据，除非已确认属于同一次报表快照和相同统计范围。

## 5. 计算指标及依赖

| 指标 | 首选公式 | 替代路径 | 周期 |
| --- | --- | --- | --- |
| Unique 付费率 | `P[n] / N` | 无，禁止从舍入后的 CPP 反推人数 | D0、D1、D3、D7、D14、D28 |
| IAP ARPPU | `I[n] / P[n]` | `S × ROAS_IAP[n] / P[n]` | 同上 |
| IAP RPD | `I[n] / N` | `S × ROAS_IAP[n] / N`；其次 `CPI × ROAS_IAP[n]` | 同上 |
| IAA RPD | `A[n] / N` | 对应 IAA 的上述路径 | 同上 |
| Total RPD | `T[n] / N` | 对应 Total 的上述路径 | 同上 |

RPD 指 Revenue per Download，在本插件中明确按归因 Installs 计算。默认显示名称示例：`D7 IAP RPD`、`D7 Unique 付费率`、`D7 IAP ARPPU`。

### ARPU 与 ARPPU 的命名边界

- 本插件的“同期群 ARPU”若选择 Installs 分母，则作为 RPD 的可选显示名称；该选项一次统一切换名称，不允许同时勾选两套重复列。提示中始终写明分母为 Installs。
- 活跃用户 ARPU／ARPDAU 需要另一个分母，当前不提供。不能用累计收入除以某日留存人数替代。
- IAA ARPPU 若表示付费用户的广告收入，应使用“付费用户群自身 IAA 收入 / 同窗口付费人数”。当前字段不足。
- Total ARPPU 若表示付费用户总价值，应使用该付费用户群的 IAP 与 IAA 收入之和，不能使用全体用户的 Total 收入。
- 若未来提供“全体收入 / 付费人数”这种业务比值，须单独命名与确认，不能默认等同于付费用户价值。

## 6. RPD 与 ROAS 增长系数

每种收入类型均支持以下 7 个组合：

| 分组 | 周期组合 |
| --- | --- |
| 相邻观察点 | D3/D1、D7/D3、D14/D7、D28/D14 |
| D1 基准 | D7/D1、D14/D1、D28/D1 |

- 公式为后期累计指标除以前期累计指标，显示 `1.50×`，表示后期为前期的 1.5 倍，不显示成“增长 150%”。
- 命名示例：`Total ROAS 倍数 D7/D3`、`IAP RPD 倍数 D28/D1`。
- 同一同期群、同收入类型、两个观察点的成本及安装分母不变时，两种增长系数均等于后期收入除以前期收入。
- 首选同类型收入比；收入不足时，可使用对应两个周期的 ROAS 比。只有数据口径一致时才允许在 RPD／ROAS 名称间复用结果。
- 计算增长系数不强制要求展示 Spend 或 Installs；同类型、同范围的两个周期 ROAS 可以构成计算路径。
- ROAS 与 RPD 两套名称均可选，允许用户明确同时展示；设置面板说明它们在相同分母下等价，默认不重复开启。
- 第一版共提供 42 个可选增长系数：2 类名称 × 3 类收入 × 7 个周期组合，使用分组和搜索避免全部铺开。

### 6.1 留存衰退系数

提供 D3/D1、D7/D3、D14/D7、D28/D7、D7/D1、D28/D1 共 6 个组合。

- 公式为后期留存率除以前期留存率，直接使用同一报表行的原生留存字段。
- 显示 `0.65×` 表示后期留存为前期的 65%，即相对衰退 35%；不把它显示成“留存率 65%”。
- 命名示例：`留存衰退系数 D7/D3`。
- 缺少任一周期的原生留存列时隐藏该增强列并保留选择；前期留存为零时保留列，该行显示 `—`。
- 后期留存为零且前期留存大于零时正常显示 `0.00×`。
- 不跨行、跨分组或跨报表拼接两个周期的留存值。

## 7. 显示选择与自动可用性

### 7.1 两个独立状态

每个增强列分别维护“用户是否选择展示”和“当前数据是否支持计算”。

`实际显示 = 插件开启 && Cohort 模式 && 用户选择展示 && 当前存在有效计算路径`

不能因为一个指标可计算就强行显示，也不能因为临时缺字段就清除用户的显示偏好。

| 用户选择 | 当前字段 | 表格行为 | 设置面板行为 |
| --- | --- | --- | --- |
| 展示 | 支持计算 | 显示增强列 | 显示已选、可计算 |
| 隐藏 | 支持计算 | 不显示 | 可以随时勾选 |
| 展示 | 缺少必要字段 | 隐藏整列；记住选择 | 保持已选，显示缺少字段 |
| 隐藏 | 缺少必要字段 | 不显示 | 仍允许勾选，说明补齐字段后自动显示 |

例：已选 `D7 IAP ARPPU`，用户移除 D7 unique purchasers 后，增强列消失；重新添加该原生字段后，增强列自动恢复。

### 7.2 字段级与单元格级区别

- 整个报表缺少依赖字段，且没有替代计算路径：隐藏整列。
- 字段存在，但某一行为空或分母为零：保留列，该行显示 `—` 并说明原因。
- 某一行首选路径无效，只有经验证可替代的路径有效时，可以按该行使用替代路径并标明来源；不得用替代路径掩盖已确认的数据矛盾。
- 分子为零且分母大于零：正常显示零。
- 未成熟：允许查看当前值，附“未成熟”标记，排除效果评价色。
- 成熟度无法确认：标注“成熟度待确认”，不冒充成熟数据。
- 公式算出非有限值或出现违反字段语义的数据：显示 `—` 和可解释原因，不能把异常强行归零。

### 7.3 自动展示与默认值

- 默认开启自动模式，显示当前可计算的全部基础指标、ROAS 增长系数及留存衰退系数；不重复开启 RPD 倍数。
- 逐列操作具有优先级：手动取消的指标即使依赖恢复也保持隐藏；手动勾选的 RPD 倍数可以显示。
- 可关闭自动模式，采用手动选择。保持旧版默认六列的配置升级为自动模式；旧自定义配置保持手动，避免覆盖选择。
- 缺字段不清除偏好；指标顺序独立于可用性，重新出现后恢复位置。默认填色不表示业务好坏。

## 8. 融入官方布局的交互

### 8.1 入口与布局

- 在原生 Columns 按钮附近增加同风格的“增强列”按钮，复用页面按钮高度、字体、边框和间距。入口明确属于插件。
- 点击后打开与原生列设置视觉一致的面板；优先采用独立面板，不把插件状态塞入官方保存接口。
- 面板分为“计算指标”“增长系数”“留存衰退”“颜色规则”，并提供按名称搜索。
- 计算指标按指标和周期列出复选项；增长系数按 ROAS／RPD、收入类型、周期组合分组；留存衰退单独列出 6 个周期组合。
- 每个具体增强列都有独立显示开关；批量选择只影响当前明确标注的分组。
- 不可用项不隐藏：显示缺少哪些字段；存在多条替代路径时给出一条可行的补齐建议。
- 支持 Apply／Cancel：应用后更新表格并保存插件偏好；取消不改变已有设置。
- 表格增强列第一版统一追加在原生列之后，支持在原生与增强列之间拖拽表头调序，或 Alt＋左右方向键移动，表头、明细、Total 与 colgroup 同步；按账号和报表保存。原生数据及列宽继续由官方管理，插件仅保存视觉顺序。
- 横向滚动、固定列和原生排序需要兼容；不能挤占或遮挡原生筛选、Cohort 切换和导出操作。

示意布局（非最终设计稿）：

```text
原生报表工具栏： [Columns] [增强列]                 [Cohort | Real time] [导出]

增强列设置
  搜索指标……
  计算指标 | 增长系数 | 留存衰退 | 颜色规则

  [✓] D7 Unique 付费率       可计算
  [✓] D7 IAP ARPPU          缺少 D7 unique purchasers
  [ ] D7 IAA RPD            可计算
  [✓] Total ROAS 倍数 D7/D3  可计算，估算路径
  [✓] 留存衰退系数 D7/D3     可计算

  已选 3 列 · 当前显示 2 列 · 1 列缺少字段
                                      [取消] [应用]
```

### 8.2 设置持久化

- 使用扩展本地存储，只保存偏好，不保存报表数据或登录凭据。
- 按站点、账号和稳定的原生 report ID 隔离设置；不能把完整 reportState 或整段含筛选信息的 URL 当作持久化键。
- 无稳定 report ID 时使用该账号的默认配置；已识别的报表在日期、分组或筛选变化时仍保留选择。
- 刷新和重新打开页面后恢复偏好；切换账号不串用另一个账号的设置。
- 插件总开关关闭后移除新增列和插件样式，恢复页面原生展示；选择偏好保留。
- 切换到 Real time 后停用本版同期群计算，提示“仅支持 Cohort”，切回后自动恢复。
- 原生保存、分享和导出不会自动包含插件设置或增强列，需要在插件面板中说明这一边界。

## 9. 区间颜色

- 可分别为受支持的原生指标列和增强列启用／关闭着色，显示开关与着色开关独立。
- 第一版支持用户配置固定数值区间、颜色，以及规则适用的收入类型和周期。
- 规则边界明确采用半开区间，例如 `[1.00, 1.50)`；拒绝相互重叠的区间。未覆盖区间使用原生底色。
- 百分比规则在界面输入百分数，例如 5 表示 5%，计算层负责比例转换。
- 初始不内置宣称好坏的业务阈值；示例值不能直接作为默认投放结论。
- 不按当前可见行的最大／最小值动态改变颜色含义，避免翻页或滚动后同一数值变色。
- 缺失、异常、成熟度未确认及未成熟的衍生单元格不套用效果评价色，保留状态提示。
- 保留数字文本及可读对比度；颜色不作为唯一信息。
- Total 行不纳入区间着色，保留原生汇总视觉；后续若需要再单独定义。

## 10. 精度、总计与数据质量

- 计算过程中不提前四舍五入，最终展示时格式化。页面显示值本身已有舍入，不能宣称等同接口原始精度。
- 建议显示：付费率 2 位小数；ARPPU 2 位小数；RPD 4 位小数；收入增长系数和留存衰退系数均保留 2 位小数并加 `×`。
- 金额沿用报表币种；无法确认币种时不自行补美元符号。
- 使用显示 ROAS 或 CPI 的替代计算路径时标记“估算”；悬浮说明公式、输入字段、数据来源及状态。
- Total 的付费率、ARPPU、RPD、增长系数和留存衰退系数从平台同口径汇总基础字段重新计算，不能平均明细行的比率。
- 平台没有可验证的汇总分母时，Total 对应值显示 `—`；不从当前可见行相加冒充完整报表，也不盲目相加跨分组去重人数。
- 无周期 Unique purchasers 不得用于带周期 ARPPU。1Y、D60、D90、D180 在字段映射核验前不纳入第一版。
- IAA 为零按已报告值展示，但不能据此断言产品没有广告变现。仅在有证据时标记回传异常。
- 同一快照内若 Total 与 IAP＋IAA 不一致，优先保留原生字段并提示待核对，不自动改写平台数据。
- 周／月同期群只在整个分组都走完窗口且满足已核验的更新规则时判定成熟；没有日级人数时不伪造精确的“成熟占比”。

## 11. 页面适配与权限边界

- 采用浏览器扩展形式；Chrome Manifest V3 为拟定方案，先完成页面适配验证。
- 不依赖固定列序号或 Campaign 显示名作为唯一关联键；优先使用经检查确认的稳定字段标识。
- 新旧数据切换时清除旧计算结果。行复用、原生重排、分页和滚动不能造成值与行错配。
- DOM 变化监听必须避免插件自身修改形成循环，不对每次变化反复全页扫描。
- 扩展侧设置与渲染不能触发官方报表保存或投放状态更新。
- 页面结构无法识别时停止相关增强并提示，保留原生报表可用，不能猜列输出看似正常的结果。
- 本版不读取或输出凭据，不申请与目标报表无关的权限，不上传业务数据。
- 原生排序后同步增强值；点击增强列表头不宣称支持全量排序。增强列排序、扩展导出为明确的范围外功能。

## 12. 验收标准

| 场景 | 必须满足的结果 |
| --- | --- |
| 字段齐全且选择展示 | 正确显示对应周期、类型和公式的增强列 |
| 可计算但用户取消展示 | 该列不显示；其他列与原生字段不受影响 |
| 已选列缺少分母字段 | 整列隐藏，设置保留已选状态并说明缺失字段 |
| 重新补齐原生字段 | 已选增强列自动恢复，不重复插入 |
| 首选字段缺失、替代路径可用 | 按规定计算并标记估算；说明实际使用的公式 |
| 某一行为空或除数为零 | 仅该单元格显示 `—`，列和其他行保留 |
| 收入为零且分母有效 | 显示真实零值，不误判为缺失 |
| 增长系数 | 7 个组合 × 3 个收入类型 × 2 种名称均映射正确；1.5 倍显示 `1.50×` |
| 留存衰退系数 | 6 个组合均按后期留存除以前期留存；0.65 倍显示 `0.65×`，前期留存为零显示 `—` |
| 未成熟与未知成熟度 | 明确标记，不套用效果评价色，不当作完整结果 |
| 只显示部分原始列 | 仅所选且存在有效计算路径的增强列显示，不强制打开全部原始列 |
| 日期、筛选、分组或分页变更 | 新值属于当前快照，不残留旧行结果 |
| 原生排序、行复用与横向滚动 | 行值对应正确，表头及单元格对齐，无重复列和明显卡顿 |
| Total | 使用可验证汇总基础字段重算；缺字段时不从可见行冒充汇总 |
| 取消设置修改 | 不改变已生效的显示选择和颜色规则 |
| 刷新、切换报表及账号 | 偏好按既定范围恢复与隔离 |
| 插件关闭／切到 Real time | 移除增强列及相关样式；恢复条件满足时按偏好重新展示 |
| 颜色区间边界 | 阈值命中唯一规则；不同分页同一数值、同一状态使用相同规则 |
| 原生功能回归 | 原生筛选、排序、分页、Columns、导出和报表保存仍按原生行为工作 |

### 数值回归样例

使用本次已读报表中的 D0 样例：Installs 为 3,331，IAP 收入为 4,924.15，Unique purchasers 为 206。

- Unique 付费率：`206 / 3331 = 6.18%`。
- IAP ARPPU：`4924.15 / 206 = 23.90`。
- IAP RPD：`4924.15 / 3331 = 1.4783`。
- 独立合成增长样例：同一同期群 D1 收入 100、D3 收入 150，则 D3/D1 系数为 `1.50×`；D1 为零时为 `—`。
- 增加零分子、缺字段、各收入类型不相同、收入回补、汇总与明细不等权等场景，防止仅验证正常路径。

## 13. 后续可选指标

以下已讨论但不进入第一版默认实现：

- 延迟首付转化：`(P[7] - P[0]) / N`，需同一同期群累计去重口径，不称为复购率。
- 区间增量 RPD：`(T[7] - T[3]) / N`，不称为 D7 单日收入。
- IAA 收入占比：`A[n] / T[n]`。
- 每安装收入与获客成本差额：`Total RPD[n] - CPI`，不称为净利润。
- 目标完成率：匹配实际 Goal type、Day target、成熟度后计算。

## 17. v0.1.1 用户反馈补充

- 默认启用数值分档填色，可单独关闭。固定档位跨分页一致；Total、零值、空值和异常值不应用默认颜色。已有自定义规则的指标不叠加默认填色。
- 颜色仅辅助比较数值大小，不表达好坏或完整周期；成熟度未知仍显示问号，自定义周期评价色继续等待成熟度确认。
- 增强列提供表头右侧拖拽手柄，范围 96–480px；双击或 Home 恢复该指标默认宽度（基础指标 116px、增长系数 132px），左右方向键每次调节 8px。表头、表体和 Total 同步，按账号／报表保存；原生列使用原生控件。
- 旧偏好保留列选择、自定义规则和总开关，缺少新字段时补上默认填色及默认宽度；显式关闭默认填色后不再自动打开。


## 18. v0.1.2 刷新恢复

- 页面自行移除增强节点或重建列宽节点时恢复增强，不能把原生删除误认为插件自己的变更。
- 首次及后续展开／收起导航时保留增强；同一账号／报表的 URL 参数变化不能单独触发清空，也不能解除正在进行的 Run 等待。
- Run 开始后等待真实表格更新或可观察的 loading 开始／结束；相同数据返回时也应恢复。
- 不使用超时将未完成的请求冒充完成。完全无可观察完成信号的请求仍保持等待提示。


## 19. 浏览器与展示类型

- 目标为桌面 Chrome、Edge、macOS Safari。Chrome／Edge 共用 WebExtension 包；Safari 使用官方工具生成宿主应用与扩展工程，不能将 ZIP 标记为 Safari 安装包。移动端不在本次范围。
- 扩展存储优先使用 `browser.storage`，没有时使用 `chrome.storage`；偏好在各浏览器本地独立保存，不跨浏览器同步。
- 「增强列」右侧增加展示类型按钮，默认按指标种类分组（付费率、ARPPU、各收入类型 RPD、ROAS／RPD 倍数、留存衰退系数），组内按观察周期排序；另一模式按 D0／D1／D3 等分组，各类倍数按后期观察点归组。
- 两种模式分别保存手动拖拽顺序；切换不改变选择、宽度、颜色或公式。旧版顺序迁移到周期模式，指标模式首次使用种类默认顺序。
- Safari 构建及真机验收状态单独记录，不用模拟 API 测试替代浏览器验收。


## 20. 展示模式、固定列与全表顺序

- 未手动定制时按展示类型提供默认分组；v0.1.4 的旧增强列顺序仍用于组内排列。
- v0.1.5 支持全表自由换位：原生列与增强列可以互相插入，手动全表布局按报表及模式保存；Date 为固定锚点，不参与换位。
- Date 表头、明细和 Total 对应单元格固定在左侧；没有 Date 时不固定其他维度。
- 显示换位不移动原生 DOM 节点，避免破坏官方列索引和取数；官方导出顺序不变。合并单元格不应用全表换位及固定，防止映射不一致。
- 新增强列默认宽度基础指标 116px、收入增长／留存衰退系数 132px，调整内边距并允许表头换行；保留已有手动宽度。双击或 Home 恢复对应默认值。
